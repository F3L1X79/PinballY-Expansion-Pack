  1. Distribution : installation et mises à jour

    Diffusionmoyen-gros

    Une Pack Version et des releases GitHub avec un ExpansionPack.zip déjà bien nommé : on l'installe à la main, sans git (zip extrait dans Scripts\, une ligne d'import). Ensuite PinballY s'occupe des mises à jour : l'Update Prompt, au démarrage avant tout le reste, propose la nouvelle version, et un helper caché la télécharge, la vérifie, permute le dossier en gardant les données du joueur, puis relance PinballY.

    idée›research›grill›spec›tickets›implement
    Spec #331, tickets #332 à #337, borne #338 (humain) ; import dynamique à essayer sur la borne #339 · ADR 0018 · Réécrit la section Install des README · Research : docs/research/distribution-install-and-updates.md
    Décisions du grilling (26/10/2026)
    • Ni .exe (SmartScreen, signature payante) ni script PowerShell à coller : première installation à la main depuis le zip, mises à jour depuis PinballY par un helper caché, comme le redémarrage (ADR 0017).
    • Vérification en arrière-plan à chaque démarrage, Update Prompt au démarrage suivant, avant le picker et le Welcome Screen (ADR 0018). Une fois par version, puis une entrée dans les Expansion Pack Settings ; seul qui voit les entrées de configuration (dernier Profile actif).
    • Vérification coupable dans .env.local et les réglages ; jamais sur une borne git. Pas de choix des Add-ons à l'installation, pas de désinstallation automatique, installeur en anglais seulement.
    • Échec : ancienne version remise, dialogue OK au démarrage suivant en attendant le toast d'erreur (TODO). Réussite : un message « mis à jour en vX.Y.Z », les nouveautés viendront avec la 1.0.
    • Script mainteneur .mjs pour publier la release (étape de build validée), sans CI.

  2. Un toast d'erreur pour les actions qui échouent

    DiffusionmoyenUI

    Un Error Toast dit à l'écran ce qu'un échec a coûté, quand le joueur ne le verrait pas autrement : une Play non enregistrée dans le Play Log, vpxtool introuvable, une Pack Update échouée. Et un Error Log, errors.log dans le dossier du pack, garde toutes les erreurs d'une session à l'autre, puisque PinballY.log repart à zéro à chaque lancement.

    idée›grill›spec›tickets›implement
    Flow Matt : /grill-with-docs → /to-spec → /to-tickets → /implement. Une famille de l'Achievement Toast (TOAST_KIND). À livrer avant le ticket #335 de la Distribution (n° ), qui l'utilisera pour l'échec de la Pack Update, sans dialogue provisoire
    Décisions du grilling (26/10/2026)
    • Toast seulement pour un échec qui coûte quelque chose et ne se répare pas seul au démarrage suivant : Play non enregistrée (au Profile qui a joué, Child et Guest compris), vpxtool introuvable avec Table ROMs activé (à un Admin Profile, à chaque démarrage tant que ça dure), Pack Update échouée (une fois, à un Admin Profile, en attendant qu'il y en ait un d'actif). Pas pour un fichier de high scores illisible, un vpxtool en erreur sur une table ni une erreur inattendue de safeHandler.
    • Les messages qui existent déjà restent : « non enregistré » et « Redémarrage impossible » des Expansion Pack Settings, message du Profile Reset, échec du téléchargement juste après « Update now ». Ils répondent à un choix que le joueur vient de faire. La réussite d'une Pack Update reste un dialogue.
    • Une famille de l'Achievement Toast : couleur propre, signe d'avertissement, même file et mêmes attentes (partie, dialogue dessiné, Welcome Screen), 10 s à l'écran. En-tête « Problème », une phrase traduite par cas (ce qui est perdu, et quoi faire pour l'Admin), traduite dans les six langues ; jamais de renvoi au journal, sauf le journal du helper pour la Pack Update.
    • Error Log : toutes les erreurs du pack (pas les WARNING), par une seule fonction qui écrit aussi dans PinballY.log ; une ligne = date et heure, Pack Version, [Script], message, la pile en retrait. Ignoré par git, gardé par la Pack Update ; au-delà de 1 Mo au démarrage il devient errors.old.log. S'il ne s'écrit pas : une seule ligne dans PinballY.log par session, jamais de toast.

    Idée de Félix du 21/10/2026, pendant le grilling des options au menu opérateur ; l'Error Log ajouté au grilling.
